# Monorepo Adaptation Analysis — SpecKit-SSD-SDLC

**Date:** 2026-06-23
**Scope:** Adapt the framework from single-project to a single-solution monorepo — one backend + multiple frontends (Next.js web, React+Vite admin, React Native mobile). Any story may be backend-only, frontend-only, or backend + one frontend.

---

## 1. Verdict

**~70% ready. Incremental adaptation, not a rewrite.**

The framework already assumes multiple surfaces (its own stack ships one backend + three frontends): the spec hierarchy, per-surface skill packs, per-consumer contracts, and platform-aware UAT exist. What's missing is **authoritative wiring** — a single source of truth telling each command *which project* a piece of work targets, where it lives on disk, and how to build/test it.

The fix is one mechanism plus three small new pieces:
- **A project manifest generated by `sk.init`** (§4) — projects + shared libraries — that ~15 commands read instead of guessing. This is the bulk of the work, but it's one shared lookup, not 15 designs.
- **Three genuinely new pieces:** surface-aware design (gap H), a dev-time API mock + typed client for the frontend (§5), and a per-surface story schema for parallel BE/FE delivery (§5).

The PO's **one-story-per-flow model does not change.** A backend + frontend story is decoupled by the **frozen API contract**, not by forking the story. This stays one solution — one spec tree, one memory layer, one ADR log. No multi-repo machinery.

---

## 2. What already works (leave alone)

- **Spec spine** (`specs/intents/.../stories/`) is solution-wide and surface-neutral.
- **`sk.contracts`** already emits per-consumer (web/mobile/admin) test plans and omits absent consumers ([sk.contracts:26-40](.claude/skills/sk.design/sk.contracts/prompt.md#L26-L40)).
- **`sk.uat`** is platform-aware (`--platform web|mobile|admin`); `sk.test`/`sk.review`/`sk.implement` are role-parameterized.
- **Contract freeze gate** exists — `validate` checkpoint after `sk.design` triggers on "Breaking API contract changes" and "Multi-frontend impact" ([checkpoint-rules.md:19-24](.claude/skills/governance/checkpoint-rules.md#L19-L24)).
- Knowledge-base tiers, ADRs, domain model — shared, correct as-is.

---

## 3. Gaps

The common cause behind A, B, E, F, G: **the active surface is *guessed*** — `sk.codegen`/`sk.scaffolding` literally say "determine the surface from context," with no field that states it and no surface→path map. C, H, I are independent.

| # | Gap | Fix |
|---|-----|-----|
| **A** | No registry mapping surface → filesystem root + toolchain (build/test/lint). | Project manifest (§4.1). |
| **B** | `role` is binary `backend\|frontend` — can't tell web/admin/mobile apart. | Add `active_surface` to session (§4.2). |
| **C** | One global `coding-standards.md` + `tech-stack.md` mixing all stacks. | Split: shared core + per-project overlay (§4.3). |
| **D** | No way to deliver a backend+frontend story by two devs in parallel — single `branch`/`status`, no `surfaces`, no dev-time mock. | Contract-as-seam + per-surface schema + dev mock (§5). |
| **E** | Plans/tasks don't declare which project root the code lands in. | `sk.planstory`/`sk.tasks` read manifest, root paths (§6). |
| **F** | Ship/test are solution-wide — can't scope to the affected project. | Scope build/test via manifest toolchain + workspace runner (§6). |
| **G** | ~7 more code-touching commands hardcode `src/{service}/` or guess the surface. | Same manifest lookup (§6). |
| **H** | Design phase is backend-only; FE-only stories still run backend architecture and emit a misleading `architecture.md`. | `sk.design` skips backend phases for FE-only units (§5/§6). |
| **I** | No model for shared code (generated API client, UI kit, shared types) — manifest covers only deployable apps. | Declare `libraries` in the manifest; workspace runner rebuilds dependents (§4.1). |

## 4. The manifest — per-project memory folders + an index

`sk.init` generates a `projects/` folder per project plus a thin **index** that routes `active_surface`. A command loads the index + shared standards, then **only** the one active project's folder.

```
.specify/memory/
├─ projects/
│  ├─ index.md                 # ROUTER: surface | one-line | type | code-root   (tiny, always loaded)
│  ├─ backend/  { project.md, tech-stack.md, coding-standards.md }
│  ├─ web/      { project.md, tech-stack.md, coding-standards.md }
│  ├─ admin/    { project.md, tech-stack.md, coding-standards.md }
│  └─ mobile/   { project.md, tech-stack.md, coding-standards.md }
└─ standards/                   # SHARED, surface-neutral (unchanged)
   ├─ coding-standards.md       # core rules: boundaries, idempotency, observability, coverage
   ├─ tech-stack.md             # shared infra only: PostgreSQL, Redis, Keycloak, observability sinks
   └─ api-standards.md · data-standards.md · observability-standards.md
```

- **`project.md`** — path root, package manager, build/test/lint commands, always-load skill packs.
- **`tech-stack.md`** / **`coding-standards.md`** (per project) — that stack's frameworks/versions and formatter/linter/error pattern.

`index.md`:
```
| surface | one-line            | type     | code root    |
|---------|---------------------|----------|--------------|
| backend | REST API + workers  | dotnet   | services/api |
| web     | Customer portal     | nextjs   | apps/web     |
| admin   | Internal admin SPA  | vite-spa | apps/admin   |
| mobile  | Customer mobile app | rn-expo  | apps/mobile  |
```

**Shared libraries (gap I).** Monorepo shared code lives in `packages/` and is declared as `libraries` (path + consuming surfaces), not as a surface:
```
libraries:
  api-client    → web, admin, mobile   (generated from api-spec.json)
  ui-kit        → web, admin
  shared-types  → all
```
A story changing a library lands in the owning surface's branch; a **workspace runner** (pnpm `-F` / Nx / Turbo) rebuilds dependents. "Scope build/test to affected" (§7, Phase 4) relies on that runner's affected-graph — name the runner in the manifest.

**4.2 `active_surface` (session.yaml).** Add one field beside `role`:
```yaml
role: null            # WHO  — po|architect|lead|backend|frontend|security  (unchanged)
active_surface: null  # WHICH — backend|web|admin|mobile                    (new)
```
`sk.session focus --story` derives it from the story's `surfaces` + `role`. Because a story has at most one frontend (§5), this resolves unambiguously.

**4.3 What splits.** Only two files: `coding-standards.md` and `tech-stack.md`. Shared/surface-neutral content stays in `standards/`; stack-specific content moves to the project folders. `api-standards.md`/`data-standards.md` stay shared (backend-only owner). Single-project repos degrade cleanly — one folder, one index row.

**The surface-resolution lookup** (`active_surface` → root + standards overlay + packs) is the *same* in every consuming command. Specify it once as a shared preamble. Moving the surface→pack map into `project.md` also deletes existing drift (today `sk.refactor`/`sk.perf` omit the mobile pack; `sk.verify` loads a web-only pack for mobile). Inject the manifest as stable `inject_files` context so prompt-cache hits are preserved.

## 5. Cross-surface delivery — the contract is the seam

The PO writes **one** user-flow story (vertical slice). It is **not** forked. A story touches the backend + **at most one** frontend. The two devs are decoupled by **freezing the API contract at the validate gate**, then working in parallel.

**5.1 Story gains `surfaces`** (≤ 2, at most one frontend; a flow needing two frontends = two stories):
```yaml
surfaces: [backend, web]   # or [backend] · [web] · [backend, mobile] …
```

**5.2 The pipeline:**
```
PO            → sk.story    → one story
BE dev        → sk.design   → architecture + api-spec.json, FROZEN at validate gate   ← THE SEAM
                  ┌──────────────────────────┴──────────────────────────┐
BE (role=backend)                              FE (role=frontend)
sk.plan --role backend                         sk.plan --role frontend
sk.implement → provider vs spec                 sk.implement → consumer vs a MOCK of spec
                  └──────────────────────────┬──────────────────────────┘
                     consumer-driven contract tests = integration safety net
```
The BE dev wears the architect hat for `sk.design`, then the backend hat. The FE dev never touches design — they read the frozen spec. **`sk.plan` gains a `--role` flag** so each dev plans only their surface (`plan-{role}.md`); today it has no role flag.

**5.3 The one real gap — a dev-time mock.** Two of three independence pillars already exist (contract freeze gate; consumer-driven contract tests). The missing one: the FE dev needs a **running mock from `api-spec.json`** (MSW / Prism) to build against, or "parallel" is a lie — they idle until the endpoint is live. The framework only mocks at *test* time ([sk.test:61](.claude/skills/sk.test/prompt.md#L61)). **Fix: `sk.scaffolding` (role=frontend) generates both the typed API client (openapi-typescript / orval, into the `api-client` library) and the MSW/Prism mock from the frozen spec.** If the spec must change after the gate, re-run `sk.design --targeted contracts`, re-freeze, and both devs rebase + regenerate client/mock.

**5.4 Per-surface branch & status.** The story has single `branch`/`test-status`/`security-status`/`verify-status` — all collide when two devs run in parallel. Make them per-surface:
```yaml
surfaces:
  backend:  { branch: null, status: draft, test-status: null, security-status: null }
  frontend: { branch: null, status: draft, test-status: null }
```
Land the frozen `api-spec.json` first (its own commit); BE and FE branch separately, integrating through contract tests. The story is `done` only when **both** surfaces reach done — both PRs landed, consumer tests passing against the real provider (`sk.ship` enforces both). `session.yaml` is gitignored = **per-developer**, so the two devs naturally hold independent sessions. **Mobile doesn't ship via PR:** `sk.ship` runs EAS build + OTA/store for `mobile`, PR+deploy for `web`/`admin`/`backend`.

**5.5 Per-role artifacts (avoid collisions).** Running the role-scoped commands twice would otherwise overwrite a single set of files. Namespace per-role execution artifacts; keep design artifacts shared:
- **Per-role:** `plan-{role}.md`, `tasks-{role}.yaml`, `review-{id}-{role}.md`, and per-surface `status`/`branch`. (Code and tests already separate by project root and test path — no change.)
- **Shared, one copy read by both:** `story-{ID}.md`, `architecture.md`, `data-model.md`, `contracts/api-spec.json`, `contracts/test-plan.md`.

Each role-scoped command reads `role` from the session and operates on its own `-{role}` file — including mode-detection (`sk.implement`: "`tasks-{role}.yaml` missing → run tasks", "`review-{id}-{role}.md` exists → refine"). `sk.verify` aggregates both roles and gates `done` on both.

**5.6 Jira (optional, isolated).** `sk.store --jira <KEY>` ingests a Jira issue (or captures manually) and feeds `sk.story`; `sk.plan --role` creates one Jira sub-task per role. Tracking only — spec artifacts stay the source of truth. Skippable entirely.

## 7. Implementation plan

Each phase is independently shippable.

**Phase 1 — manifest (the keystone).** `sk.init` generates the `projects/` tree (index + per-project `project.md`/`tech-stack.md`/`coding-standards.md`); trim `standards/coding-standards.md` + `tech-stack.md` to shared. Add `active_surface` to `session.yaml` + `sk.session`. *No behaviour change yet — everything below becomes a lookup.*

**Phase 2 — make commands read the manifest.** Author the shared surface-resolution preamble; apply to `sk.scaffolding`/`sk.codegen`/`sk.tasks` (root paths, drop the duplicated 4-way branch), `sk.implement`/`sk.review` (standards overlay), and the gap-G commands (root their `src`/test/migration paths). Point `CLAUDE.md` at the manifest.

**Phase 3 — design + parallel delivery (the new logic).** Gap H (`sk.design` skips backend phases for FE-only). Add `surfaces` to `story-template.md` + `sk.specify`. Add `sk.plan --role` + the per-surface branch/status schema (`sk.session`/`sk.ship` aware). Add FE typed client + dev-time mock to `sk.scaffolding`; `sk.ship` per-surface ship strategy.

**Phase 4 — scope ship/test (polish).** `sk.test`/`sk.ship` build/test only affected projects via the workspace runner's affected-graph (also rebuilds dependents of changed `libraries`); `sk.ship` uses the per-surface strategy (PR+deploy vs mobile EAS/store); `sk.impact` reports per-surface blast radius.

**Phase 5 — Jira (optional, independent).** `sk.store` intake + per-role sub-tasks. Anytime or never.

*Phases 1→2 ship value immediately. Phase 3 is the only net-new logic. Phases 4–5 are optional.*

---

## 8. Risks & non-goals

- **FE building against a stale spec** — mitigated by the freeze gate + regenerating the mock from the frozen spec. The shared spec is the only source.
- **Two-branch "done" race** — a story isn't done until both PRs land and consumer tests pass against the real provider; `sk.ship` must enforce both.
- **Gap H produces a *wrong* artifact** (backend `architecture.md` for an FE-only story), not just a misplaced one — prioritize it.
- **Non-goal — multi-repo.** Stays one solution, one spec tree, one memory layer.
- **Non-goal — per-project KBs or rewriting skill packs.** Unit KB is shared; only the pack *selection wiring* moves to data.
